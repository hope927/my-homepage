# 需求文档

## 1. 应用概述

**应用名称**：hope的个人主页

**应用描述**：一个简约风格的个人主页网页，用于展示个人信息并提供数字分身聊天功能，面向朋友和潜在合作伙伴。

## 2. 用户与使用场景

**目标用户**：
- 朋友
- 潜在合作伙伴

**核心使用场景**：
- 访客快速了解hope的基本信息、当前状态和兴趣方向
- 访客通过数字分身聊天区与hope进行初步交流，获取常见问题的答案

## 3. 页面结构与功能说明

### 3.1 页面结构

```
个人主页（单页面）
├── 头部区域
│   ├── 头像
│   ├── 名字
│   └── 一句话介绍
├── 个人信息展示区
└── 数字分身聊天区
```

### 3.2 功能说明

#### 3.2.1 头部区域

**头像**：
- 展示用户头像
- 支持用户点击上传本地图片文件，上传后实时预览替换头像

**名字**：
- 展示「hope」

**一句话介绍**：
- 展示「一个正在学习用ai做网页，最终ai赚钱的求学者」

#### 3.2.2 个人信息展示区

展示以下信息：
- **我现在主要在做**：跟着ai用提示词制作网站。
- **我的兴趣**：学习ai和旅行。
- **我一个比较有记忆点的特点是**：e人。

#### 3.2.3 数字分身聊天区

**功能**：
- 访客在输入框中输入问题，点击发送按钮提交
- 系统根据预设知识库匹配问题，返回对应答案并展示在聊天记录中
- 聊天记录以对话形式呈现，区分访客提问和数字分身回答

**预设知识库**：
- 问题1：你接触ai多久了？
  - 答案：我之前做过销售，干过工地，现在沉下心来学习ai的知识，接触时间不算长，但正在全力投入。
- 问题2：你擅长用ai干什么？
  - 答案：我擅长用ai进行创作，目前主要跟着ai学习制作网页作品，关注ai创作和创收方向。
- 问题3：你有ai创收的方向吗？
  - 答案：我正在探索ai创收的方向，目前专注于用ai制作网页，希望未来能通过ai实现盈利。
- 其他问题：
  - 答案：感谢你的提问！这个问题我暂时没有准备答案，欢迎直接联系我深入交流。

## 4. 业务规则与逻辑

### 4.1 头像上传规则

- 用户点击头像区域触发文件选择
- 选择图片文件后，使用本地预览方式即时替换头像显示
- 不涉及后端存储，刷新页面后恢复默认头像

### 4.2 数字分身问答匹配规则

- 访客输入问题后，系统对问题进行关键词匹配
- 匹配逻辑：
  - 若问题包含「接触」「多久」等关键词，返回问题1的答案
  - 若问题包含「擅长」「干什么」等关键词，返回问题2的答案
  - 若问题包含「创收」「方向」等关键词，返回问题3的答案
  - 若无法匹配，返回其他问题的通用答案
- 匹配结果展示在聊天记录中

### 4.3 移动端适配规则

- 页面布局需适配手机屏幕尺寸
- 各功能区域在移动端垂直排列，保持可读性和可操作性

## 5. 异常与边界情况

| 场景 | 处理方式 |
|------|----------|
| 用户上传非图片格式文件 | 提示「请上传图片文件」，不执行上传操作 |
| 用户未输入问题直接点击发送 | 提示「请输入问题后再发送」，不执行发送操作 |
| 数字分身无法匹配问题 | 返回通用答案「感谢你的提问！这个问题我暂时没有准备答案，欢迎直接联系我深入交流。」 |

## 6. 验收标准

1. 访客打开个人主页，看到头像、名字「hope」、一句话介绍「一个正在学习用ai做网页，最终ai赚钱的求学者」
2. 访客查看个人信息展示区，看到「我现在主要在做」「我的兴趣」「我一个比较有记忆点的特点是」三项信息
3. 访客点击头像，选择本地图片文件上传，头像实时更新为上传的图片
4. 访客在数字分身聊天区输入「你接触ai多久了？」，点击发送，看到数字分身返回对应答案
5. 访客在移动端打开页面，各功能区域正常展示且可操作

## 7. 本期不实现功能

- 用户登录/注册功能
- 后端数据存储（头像上传、聊天记录等均不持久化）
- 数字分身接入真实大模型API
- 个人信息编辑功能
- 社交分享功能
- 访客留言或评论功能
- 多语言切换功能
- 深色模式切换功能
